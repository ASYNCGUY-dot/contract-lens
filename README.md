# 계약서 돋보기 / Contract Lens

동아AI랩 3기 3차 프로젝트 **V1-2 트랙**. 공익 목적.

계약서·약관을 넣으면 **판정하지 않고**, 해당 조항과 관련 법 조문을 나란히 놓아
일반인이 스스로 판단할 근거를 만들어 준다.

## 지금 실력 — 먼저 밝힌다

| | 표준약관 85개 | 실제 사설 약관 41개 |
|---|---|---|
| 1순위가 정답 | 70.9% | 41.7% |
| 3개 안에 정답 | 94.5% | 75.0% |
| 보여준 것 중 실제 관련 | 93.1% | 27.0% |

**왼쪽 수치를 이 도구의 실력이라고 읽으면 안 된다.** 표준약관은 공정거래위원회
심사를 거친 문서라 실사용 입력과 성격이 정반대다. 판례에서 분쟁이 된 실제 약관으로
재면 오른쪽이 나온다.

읽는 법은 이렇다. **관련 조문을 후보 세 개 안에 넣는 일은 실제 약관에서도 된다
(75.0%). 관련 없는 조항을 관련 없다고 말하는 일은 안 된다(27.0%).** 그래서 조항
대부분에 후보가 붙고, 1순위가 정답이라는 보장이 없다. 화면에 확신도 등급을 두지
않고 순위만 주는 것도 그 때문이다.

표본이 41~85개로 작다. 수치마다 신뢰구간을 함께 재 두었고 상세는
[docs/NOTES.md](docs/NOTES.md)에 있다.

## 무엇을 하고 무엇을 하지 않는가

**한다**

- 계약서 조항을 「약관의 규제에 관한 법률」이 열거한 불공정 유형과 대조
- 관련 가능성이 있는 조문을 관련도 순위로 최대 3개 제시
- 조문 원문과 각 호, 효력(무효·추정), 쉬운 안내, 용어 풀이를 나란히 표시
- 목적·정의처럼 문서 자체를 설명하는 조항은 대조하지 않고 그 사실을 밝힘
- 결과를 텍스트 파일로 내려받기

**하지 않는다**

- "이 조항은 무효입니다" 같은 **법적 판단**
- 개별 사실관계 파악 · 법규 검토 · 법적 추론
- 변호사 연결이나 유료 검토 알선

이 경계는 취향이 아니라 **법적 요건**이다. 2026년 대법원 판결(3부, 주심 오석준)은
법률사무에 해당하려면 **구체적·개별적 사실관계 파악 + 적용 법규 검토 + 법적 추론·평가**가
필요하다고 봤고, *"이용자가 공란을 채우면 수정 없이 그대로 문서에 반영되는 형태"* 는
법률사무가 아니라고 판단했다. **판정을 하는 순간 위법 영역으로 들어간다.**

## 왜 이 구조가 정확한가

법률이 직접 유형을 열거한다. 「약관의 규제에 관한 법률」 제7조~제14조가 불공정 조항 유형을
구체적으로 적고 각각 "무효로 한다"고 명시한다.

```
제7조(면책조항의 금지) 1호
  사업자, 이행 보조자 또는 피고용자의 고의 또는 중대한 과실로 인한
  법률상의 책임을 배제하는 조항
제9조(계약의 해제·해지) 1호
  법률에 따른 고객의 해제권 또는 해지권을 배제하거나 그 행사를 제한하는 조항
제14조(소송 제기의 금지 등) 1호
  고객에게 부당하게 불리한 소송 제기 금지 조항 또는 재판관할의 합의 조항
```

그래서 **AI는 판정하지 않고 매칭만 한다.** "이 조항이 법 제몇조 몇호 유형과 형태가 같은가"를
분류하고, 답은 조문에서 그대로 옮긴다. 매칭이 애매하면 후보를 보여주고 사용자가 고른다.

**틀릴 여지가 매칭 한 곳에만 있고, 그 정확도는 계약서 표본으로 측정된다.**

## 데이터

전부 [법제처 국가법령정보 공동활용](https://open.law.go.kr) API 로 직접 수집했다.

| 데이터 | 규모 | 리포 포함 |
|---|---|---|
| 약관규제법 불공정 유형 | 28개 | 포함 |
| 조문 전문 | 33개 조 / 105문장 | 포함 |
| 표준약관 | 39건 | 포함 |
| 판례 색인 (사건번호·참조조문) | 463건 | 포함 |
| **판례 본문** | **463건 7.5MB** | **제외** — 아래 참조 |

**`JO` 참조조문 필터는 조문 번호를 신뢰할 수 없다.** `JO=제7조`로 229건이 나오지만
그 판례들의 실제 참조조문에는 제7조가 없다. 수집만 `JO`로 넓게 하고,
조문별 색인은 본문 참조조문을 직접 파싱해서 만든다. 상세는
[docs/api-notes.md](docs/api-notes.md).

조문별 판례 수 (본문 참조조문 기준, 463건 중 410건에서 약관법 조문 검출):

```
제3조(명시·설명의무) 106   제5조(해석) 108   제6조(일반원칙) 138
제7조(면책조항)       19   제9조(해제·해지) 18   나머지 1~3건
```

**제7~14조의 구체적 유형은 판례가 거의 없다.** 실무에서 다투는 것은 제3·5·6조다.
이 도구가 제7~14조만 다루는 것은 그래서 한계이기도 하다.

### 판례 본문을 리포에 넣지 않은 이유

법제처 이용안내는 "영리 목적 포함 자유로운 활용 보장"이라면서도 **제3자 재배포에
대해서는 명시가 없다.** 그리고 판례 본문에는 법인명과 변호사 실명이 그대로 들어
있어, 463건 수집본을 그대로 올리는 것은 '활용'보다 '재배포'에 가깝다고 판단했다.

`data/cases/bodies.jsonl` 은 커밋 이력에서도 지웠다. 아래로 직접 받으면 된다
(본인 `LAW_OC` 필요).

```bash
python src/collect_cases.py
```

**서비스 동작에는 필요 없다.** 조항 대조와 조문 원문 보기는 판례를 쓰지 않는다.
평가 세트를 새로 만들 때만 쓴다.

## 프로젝트 배경

동아AI랩 3기 3차 개인 프로젝트다. 2026년 8월 23일에 시작해 10월 12일에 발표한다.

만드는 동안의 판단과 실패를 [docs/NOTES.md](docs/NOTES.md)에 모듈 19개로 남겼다.
잘된 것보다 **틀린 진단을 정정한 기록**이 많다. 문체가 원인이라고 봤다가 대조군으로
반증한 것, 정확도 97.9%가 쉬운 표본에서 나온 값이라 폐기한 것, 조문별 신뢰도가
과적합이라 롤백한 것 따위다. 설계 근거를 알고 싶으면 코드보다 그쪽이 빠르다.

제출용 문서는 [docs/](docs/)에 있다.

## 실행 방법

파이썬 3.12, Node 20 이상에서 확인했다. 윈도우 기준으로 적었다.

### 1. 설치

```bash
python -m venv .venv
.venv\Scripts\activate      # macOS·Linux 는 source .venv/bin/activate
pip install -r requirements.txt
```

### 2. 모델 준비 (처음 한 번)

임베딩 모델을 ONNX로 바꿔 둔다. **441MB라 리포에 넣지 않았다.**

```bash
python src/build_onnx.py
```

`models/onnx/`가 생긴다. 이 단계를 건너뛰어도 되는데, 그러면 torch로 모델을
올리므로 메모리를 711MB 쓴다(ONNX는 650MB). 개발 중에는 어느 쪽이든 상관없다.

### 3. API 서버

```bash
uvicorn src.api:app --port 8000
```

기동에 4초 정도 걸린다. 임베딩 모델을 시작할 때 한 번만 올리기 때문이다.
`http://127.0.0.1:8000/docs`를 열면 API를 바로 시험해 볼 수 있다.

ONNX로 돌리려면 `USE_ONNX=1`을 붙인다.

### 4. 화면

```bash
cd web
npm install
npm run dev
```

`http://localhost:5173`이 열린다. API 서버가 떠 있어야 분석이 된다.
안 떠 있으면 화면이 그 사실과 실행 명령을 알려 준다.

### 5. 테스트

```bash
python tests/test_api.py
```

10개가 모두 통과해야 한다. pytest 없이도 돌아간다.

```bash
python -m pytest tests/ -v
```

### 지인에게 링크를 보내려면

```powershell
.\서비스_켜기.ps1
```

서버와 터널을 함께 띄우고 `trycloudflare.com` 주소를 알려 준다. 그 주소를
지인에게 보내면 바로 쓸 수 있다.

**이 창을 닫으면 서비스가 꺼지고 주소도 사라진다.** 다시 켜면 주소가 바뀌므로,
"오늘 저녁까지 열어 둘게" 식으로 시간을 정해 공유하는 편이 낫다.

터널 실행 파일은 `tools/cloudflared.exe` 에 둔다(53MB, 리포에는 넣지 않는다).
없으면 [Cloudflare 공식 저장소](https://github.com/cloudflare/cloudflared/releases/latest)에서
`cloudflared-windows-amd64.exe` 를 받아 그 이름으로 두면 된다.

후기는 화면의 **[후기] 탭 → [운영자]** 에서 `.env` 의 `ADMIN_KEY` 로 볼 수 있다.

### 환경변수

`.env.example`을 `.env`로 복사해 채운다. **`.env`는 커밋하지 않는다.**

| 이름 | 필요한 곳 | 없으면 |
|---|---|---|
| `LAW_OC` | 법령·판례 재수집 (`collect_cases.py` 등) | 이미 받아 둔 `data/`로 충분하다 |
| `OPENAI_API_KEY` | LLM 구조 추출(선택 기능), 평가 도구 | 매칭과 화면은 그대로 동작한다 |

**API 키가 없어도 핵심 기능은 전부 돌아간다.** 조항 대조와 조문 원문 보기는
로컬 임베딩만 쓴다.

### 데이터를 다시 만들려면

`data/`는 판례 본문만 빼고 채워져 있다. 아래는 재현이 필요할 때만 쓴다.
전부 본인 `LAW_OC` 가 있어야 한다.

```bash
python src/build_law_index.py      # 약관규제법 유형 28개
python src/fetch_full_law.py       # 조문 전문 (조문 원문 보기에 쓴다)
python src/collect_cases.py        # 판례 463건  (오래 걸린다)
python src/collect_terms.py        # 표준약관 39건
```

### 성능을 다시 재려면

```bash
python src/score_eval_v2.py        # 표준약관 85개
python src/score_eval_v3.py        # 판례 인용 조항 41개
```

이용안내가 정한 의무이므로, 이 리포의 데이터를 다시 쓸 때도 같은 표기를 남겨야 한다.

없다. 조문이 무엇에 관한 것인지만 적었으며 어떤 계약서 조항이 불공정한지는 말하지
않는다.

## 고지

**이 도구는 법률 자문이 아니다.** 관련 가능성이 있는 조문을 제시할 뿐 불공정 여부를
판정하지 않는다. 실제 판단에는 변호사 등 전문가의 검토가 필요하다.

입력한 계약서는 **저장하지 않는다.** 분석에만 쓰고 응답 후 버린다.
